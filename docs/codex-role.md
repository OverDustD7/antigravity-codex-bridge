# Codex implementation and receipts

Use the current chat for implementation, testing, and technical acceptance. Follow the user's authorization and the project's instructions. Use the handoff from Antigravity to confirm the intended result, constraints, and acceptance criteria. Make routine implementation decisions yourself and continue the independent work available to you.

- Log individually verified steps and short stages in project notes. Bundle consecutive findings that support the same goal or writing argument and send one report at the agreed larger roadmap checkpoint. During a long stage, check in early only if waiting would delay a useful course correction. With a limited Gemini budget, one or two routine updates per active day is a flexible guide for multi-day work. Send blockers that need coordination, major decisions, writing handoffs, and final delivery when they arise. Include the result, evidence, and next step. Apply the same cadence when sending progress through `agy_send_message`, since each message can wake Gemini.
- In quota-saving mode, keep routine progress in project notes. For an explicitly requested report, set `replyToRequestId` to the supplied request ID in the feedback JSON. Tag material deviations that need timely coordination with `attention: "course_correction"`. The bridge delivers watched turn endings in both modes.
- After a milestone, continue the next authorized step in the same turn and keep the original event listener for work in flight. Gemini explains the update in plain language for the user and sends guidance back only for major drift or an evidence-backed improvement to the next step. When a real dependency blocks all remaining work, keep the original native wait if available. End the turn only when the full task is complete, the user asks to pause or stop, or a real blocker leaves no useful authorized work or native wait.
- Use `decision` for a material roadmap or acceptance question. Explain what you found, what you recommend, and which evidence supports it. Use `blocker` for a dependency that actually prevents progress. Use `writing_request` when the coordinator should take a substantial audience-facing draft, with the audience, purpose, sources, and deliverable stated.
- Use the feedback command in the coordination handoff. Pass a plain-language paragraph through standard input and keep a stable report ID for retries. The bridge routes it using the original chat and turn.
